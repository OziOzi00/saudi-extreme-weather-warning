# 架构与边界

```text
MAZU 2025 ───────────────> 指标统计、规则与图谱纠错方法开发

GraphCast 2018 / 2020 ──> MAZU-like NetCDF ──> ADM1指标摘要
  ──> 基础风险规则 ──> 预测时知识图谱纠错 ──> 联合最终风险与预测锁
  ──> Neo4j关系查询 ──> 八阶段编排Agent ──> 系统/大模型双轨报告与双锁
                                                        │
                                                        └─ 锁定后
                                                           IMERG / SSOD / GHCN / 灾害记录
                                                           ──> 天气层与影响层事后验证
```

## 已实现的数据链路

A 的 `run_case.py` 和 `run_batch.py` 已实现 GraphCast 2018/2020 的远程读取、缓存、MAZU-like v1 转换和 24/48/72 小时 NetCDF 输出。批处理以 CSV catalog 为输入，并在 manifest 中记录状态；区域汇总把每份网格预报确定性聚合为13个ADM1、11项指标。小型正式交接文件位于 `handoff/mazu_like/`。

## 业务层实现状态

`risk/` 保留基础风险并实现联合候选选择和独立回放：暴雨234组、高温2316组，每组由基础气象规则和预测时图谱纠错共同产生`joint_final_risk`。`knowledge_graph/` 隔离无真值预测快照与事后评估图谱；联合在线节点使用独立`JointPrediction*`标签，运行查询不能访问同期观测或灾害答案。`orchestration/` 提供可恢复的八阶段工作流和受控控制器，`agent/` 负责结构化双轨报告：系统结论不可改写，大模型意见独立生成、锁定并评分。暴雨联合研究候选通过development门槛但尚无独立纠错增益证据，高温候选未通过全部门槛并强制blocked。本地真实联调不等于生产部署，所有报告均为研究回放产物而非业务预警。

职责和交接由[三人分工与协作流程](团队协作流程.md)统一说明：A 维护预测事实，B 维护风险与天气验证事实，C 维护区域/灾害真值及图谱整合。

## 技术边界

- NetCDF 保存栅格级气象数据；预测图谱只保存单次 case、窗口、区域、冻结风险、规则和一致性检查，验证图谱才保存观测、影响、验证和来源等事后关系。
- GeoPandas/Python 将承担区域聚合和 YAML 风险规则执行；Neo4j Community 用于关系和证据组织。
- 图谱可参考 SOSA/SSN、QUDT、OWL-Time、PROV-O、DMDO 的语义映射，但 v1 并未部署完整 OWL、GeoSPARQL 或任何外部图谱系统。
- 预测阶段的 Agent 只能读取预测锁、过程指标、图谱时间线和方法边界；不得读取同期/事后真值、发明阈值或补造证据。系统轨结论不可改写；大模型轨只能形成单独意见。两轨锁定后才能运行 Verification。
- 图谱纠错是联合预测器中显式、可审计的一环，可以按已锁定规则修正联合风险；它不能调用同期答案，也不能由大模型临时改写。旧“影子建议”方案仅保留为历史审计。

MAZU 2025 只承担指标与方法参考；联合候选只能在明确的development划分中选择并写入选择锁，independent_test不得参与选型或事后回调。

面向结项材料的模块、证据和阅读顺序见[项目总览与答辩交接](../项目总览与答辩交接.md)。
