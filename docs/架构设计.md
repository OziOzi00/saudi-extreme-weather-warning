# 架构与边界

```text
GraphCast 2020 ── A ──> MAZU-like NetCDF ── B ──> 冻结 Risk JSON
                                                        ├─> 无真值预测快照 ─> 影子纠错 ─> Forecast Agent
                                                        └─> 输出锁定
                                                             └─> IMERG / GHCN / 灾害记录
                                                                  └─> 验证图谱 ─> Verification 报告
MAZU 2025 ──────────> B：开发统计、规则标定与冻结
```

## 已实现的数据链路

A 的 `run_case.py` 和 `run_batch.py` 已实现 GraphCast 2020 的远程读取、缓存、MAZU-like v1 转换和 24/48/72 小时 NetCDF 输出。批处理以 CSV catalog 为输入，并在 `manifests/processing_manifest.csv` 记录状态。现有演示交接文件真实存在于 `handoff/mazu_like/`。

## 业务层实现状态

`risk/` 已完成草案试跑、暴雨 v2 冻结、development 正式生成和一次性独立暴雨回放。`knowledge_graph/` 同时保留两类互不替代的产物：`prediction_kg_bundle_v2` 是逐次预测、无真值的只读快照；`kg_bundle_v1` 是输出锁定后的评估图谱，并已在本地 Neo4j Community 2026.06.0通过87节点、152关系、6约束和三组固定查询验收。预测快照现可读取满足截止时间的WorldClim静态区域背景，并运行不接触真值的v2影子纠错。`agent/` 也拆分为 Forecast v2 与 Verification v1；Luna 已真实生成 `truth_accessed=false` 的结构化预测报告。暴雨v2是唯一正式气象规则；高温12组统一候选均未通过development门槛；图谱v2只能报告`triggered_not_activated`影子建议，不能改写冻结风险。本地 Neo4j 联调不等于生产部署，所有报告均为研究回放产物而非业务预警。

职责和交接由[三人分工与协作流程](团队协作流程.md)统一说明：A 维护预测事实，B 维护风险与天气验证事实，C 维护区域/灾害真值及图谱整合。

## 技术边界

- NetCDF 保存栅格级气象数据；预测图谱只保存单次 case、窗口、区域、冻结风险、规则和一致性检查，验证图谱才保存观测、影响、验证和来源等事后关系。
- GeoPandas/Python 将承担区域聚合和 YAML 风险规则执行；Neo4j Community 用于关系和证据组织。
- 图谱可参考 SOSA/SSN、QUDT、OWL-Time、PROV-O、DMDO 的语义映射，但 v1 并未部署完整 OWL、GeoSPARQL 或任何外部图谱系统。
- Forecast Agent 只能调用无真值查询并据已有 Risk JSON、预测快照和合法知识先验撰写报告；不得读取同期/事后真值，不得自行计算气象指标、发明阈值或补造证据。Verification Agent 只能在预测输出锁定后运行。
- 图谱可以标记“内部气象条件与低风险结论存在冲突”，或在未来有合法截止时点前知识时给出低置信先验；两者都不能静默改写冻结风险等级。

规则必须先在 MAZU 2025 上标定并冻结，才可用于 2020 独立回放；不得根据 2020 回放结果反向调参。
