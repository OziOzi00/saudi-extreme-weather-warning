# 2026-07-17 高温冷偏差修正预注册方案

## 状态

本方案在运行修正后的交叉验证结果之前写入并版本化。它只使用6个已批准高温`development`案例，不读取`20200729_00`独立高温案例。详细机器可读口径见`configs/heatwave_bias_correction_cv_v1.yaml`。

## 为什么需要这一步

SSOD同站点`station_max`配对显示，18个TMAX lead的MAE为2.053°C、RMSE为2.201°C、Bias为-2.053°C，且高温v2在7个事件目标窗中只命中1个。该现象支持“GraphCast/空间口径存在系统性冷偏差”作为development假设，但不能直接把2.053°C加到所有预报后在同一数据上宣称成功。

## 预注册方法

1. 使用留一案例法，共6折；每折完整留出一个高温development案例。
2. 仅用其余5个案例中`accepted`、`tmax_c`、`station_max`配对，计算`observed - forecast`的中位数。
3. 把折内修正限制在-4°C至+4°C，然后只加到留出案例区域摘要的`tmax_c`字段；`tmin_c`、降水和动力字段不变。
4. 高温v2的47°C/49°C阈值、风险评分、案例角色、目标时间窗和置信度上限全部不变。
5. 使用修正后的留出案例结果合并计算目标窗召回、特异度、事件案例检出率和对照案例拒绝率。

## 预注册成功门槛

- 事件案例不少于3个、对照不少于2个；
- 目标窗召回率不低于0.60；
- 特异度不低于0.80；
- 事件案例检出率不低于0.666667；
- 所有对照案例必须保持低风险；
- 最终全development固定修正量的绝对值不得超过4°C；
- 正式观测QC必须全部为`accepted`。

只有全部满足时，才允许使用全部development案例估计一个固定修正量并形成待冻结的高温v3候选。否则高温规则继续保持`draft`，独立高温案例继续封存。交叉验证即使通过，也仍然只是development证据。

## 锁定输入

配置文件固定了development配对、ADM1摘要、案例目录和高温v2规则的SHA-256。运行器必须先核对散列；任何输入变化都应使本方案失效，而不是静默重算。
