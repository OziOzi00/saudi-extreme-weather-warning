# IMERG/GHCN 天气观测接入与验证

本文件说明观测接入框架及实际数据状态。2026-07-17已在本地准备GHCN-Daily 2020年文件，以及32个IMERG Final Run V07B日累计文件。development配对已闭合；暴雨v2冻结后又完成一次性独立暴雨评估。

## 数据源边界

### IMERG 降水

- 官方入口：NASA GPM IMERG 数据页 <https://gpm.nasa.gov/data/imerg>。
- 研究回放优先使用 Final Run，并固定产品版本、文件名、下载时间和校验值。NASA 说明 Early/Late/Final 的时效和校准方式不同，不能混成一个观测序列。
- IMERG 文件可能给出 `mm/hr` 率或 `mm` 累积量。率值必须乘时间间隔后再累加；不能直接把 48 个半小时率相加后仍写成 mm。
- NASA Earthdata/PPS 访问可能需要免费账户。认证信息只放本机环境或凭据文件，禁止提交 Git。

### GHCN-Daily 温度

- 官方目录：NOAA NCEI <https://www.ncei.noaa.gov/pub/data/ghcn/daily/>。
- 年文件入口：`https://www.ncei.noaa.gov/pub/data/ghcn/daily/by_year/{year}.csv.gz`。
- `TMAX`、`TMIN` 和 `PRCP` 的归档值按官方格式使用十分之一摄氏度或十分之一毫米，标准化代码会除以 10。
- `Q_FLAG` 非空的记录标为 `rejected`，不得进入正式指标；站点数量必须写入配对记录。
- GHCN 的日界线和观测时刻不必等于 UTC 00–24h。正式验证前必须结合站点 `OBS-TIME` 或资料说明确认，与 GraphCast UTC 窗口不完全一致时应标为时间匹配限制。
- NOAA官方格式文档定义`OBS-TIME`为站点当地观测时间，且该字段可缺失；当前development涉及的沙特记录为空。因此本轮只允许连续量临时诊断，不允许正式温度、分类技能或热浪时序结论。

## 匹配原则

1. 时间必须使用 A 的 `valid_start_time` 和 `valid_end_time`，IMERG 采用左闭右开窗口 `[start, end)`。
2. IMERG 与预测使用同一 ADM1 边界和同一聚合量，例如双方都采用 `spatial_p95`；不得拿预测最大值和观测均值直接计算误差。
3. GHCN 是离散站点。预测值应采样到同一批站点后再计算 `station_mean/max/min`，不能与整区格点 P95 假装同口径。
4. `coverage_fraction`、`station_count`、`observation_id` 和 `qc_status` 必填。覆盖不足的记录先标 `provisional` 或 `rejected`，不进入正式指标。
5. 原始观测留在 `data/external/` 或团队约定的共享存储，不提交 Git；仓库只保存小型目录、配对摘要和可追溯校验信息。

## 运行指标框架

区域/站点空间匹配需要可选依赖：`pip install -e ".[verification]"`。纯指标计算仍只使用项目基础依赖。

准备符合模板的配对 CSV 后运行：

```powershell
$env:PYTHONPATH = "$PWD\src"
python -m saudi_warning.verification.run_weather_verification path\to\pairs.csv
```

GHCN 下载和本地标准化示例：

```powershell
$env:PYTHONPATH = "$PWD\src"
python scripts\download_ghcn_year.py 2020 --include-stations
python -m saudi_warning.verification.prepare_observations ghcn `
  --year-file data\external\ghcn_daily\2020.csv.gz `
  --stations-file data\external\ghcn_daily\ghcnd-stations.txt `
  --output outputs\weather_verification\ghcn_adm1_2020.csv
```

IMERG 需要先从 NASA 官方入口取得与 case 对应的本地文件，再运行 `prepare_observations imerg --input ... --valid-start ... --valid-end ... --output ...`。脚本不会猜测产品版本或替用户处理 Earthdata 凭据。

IMERG 下载计划和认证下载：

```powershell
$env:PYTHONPATH = "$PWD\src"
python scripts\download_imerg_daily.py

# 在 NASA PPS 注册并验证邮箱后，仅在当前终端设置，不写入文件：
$env:PPS_EMAIL = "你的注册邮箱"
python scripts\download_imerg_daily.py --download
Remove-Item Env:PPS_EMAIL

# 或运行交互式包装脚本，邮箱不会进入命令历史：
powershell -ExecutionPolicy Bypass -File scripts\run_imerg_download.ps1
```

NASA PPS 当前说明注册邮箱同时作为用户名和默认密码；工具也允许通过本机临时环境变量 `PPS_PASSWORD` 覆盖。任何凭据都不得写入配置、日志或 Git。

默认输出到被 Git 忽略的 `outputs/weather_verification/`。只有在 B 核对数据来源、时间日界线、单位、覆盖率和结果后，才讨论哪些小型验证摘要进入正式 handoff。

当前development连续指标可复验为：

```powershell
$env:PYTHONPATH = "$PWD\src"
python -m saudi_warning.verification.run_development_diagnostics
```

输出为`handoff/weather_verification/development_continuous_metrics.csv`。入口会校验7个冻结的development case_id、禁止阈值非空、限制accepted来源为IMERG，并把GHCN结果单独标为`provisional_diagnostic_not_formal`。

## 2026-07-16 实际核验结果

- 本机已有 `data/external/ghcn_daily/2020.csv.gz` 和站点表；原始文件被 Git 忽略，散列和状态记录在 `manifests/observation_source_availability.csv`。
- 32 个 GHCN 站点落入当前固定 ADM1 边界。候选覆盖和逐日摘要已写入 `manifests/ghcn_2020_candidate_coverage.csv` 与 `manifests/ghcn_2020_saudi_daily_summary.csv`。
- 7 月末高温候选有明确 GHCN 高温信号；多数降水窗口的站点 PRCP 覆盖不足，不能替代 IMERG 区域降水验证。
- IMERG 32个UTC日文件均完成ZIP与SHA-256校验，总计385,242,883字节；其中22个覆盖案例窗口、6个补齐development lead、4个补齐锁定的独立暴雨评估。原始文件位于被Git忽略的`data/external/imerg_final_v07b/`。
- 日累计 GeoTIFF 按官方规则使用 0.1 mm 缩放并把 `29999` 作为缺测；22 日×13 区逐日摘要、11 条案例区域窗口摘要和 5 条对照比较记录位于 `manifests/imerg_2020_*.csv`。
- 4 个暴雨对照在其目标区域内的窗口 P95 与最大值均低于 31 天内匹配事件，因此标为 `imerg_screened_lower_intensity`；这表示相对低强度，不等同于“无雨”或可靠的“无灾害影响”。
