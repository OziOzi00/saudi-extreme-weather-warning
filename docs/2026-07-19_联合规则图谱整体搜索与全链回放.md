# 联合规则—图谱整体搜索与全链回放

## 1. 本轮纠正的评估对象

本轮不再把风险规则和知识图谱拆成两个互不影响的模块。每一个候选都表示完整系统：

```text
GraphCast → MAZU-like → 基础气象规则 → 多窗口预测图谱 → 联合最终风险
```

图谱在候选评估中可以改变“联合研究输出”，但推理时仍禁止读取同期观测、事件角色、灾害影响和命中/漏报答案。程序先用全部24/48/72小时预测产生联合结果并锁定，再用development或独立真值评分。

## 2. 搜索规模与选择标准

- 暴雨：234组，覆盖v1/v2基础规则、11档单窗降水比例、4档支持证据数，以及跨2或3个lead的持续性组合。
- 高温：2316组，覆盖12种偏差/空间聚合基础方案，以及临界温度、跨lead持续性、区域最大值佐证、OR/AND组合。
- 统一评分同时考虑目标日/窗口召回、非事件特异度、事件案例检出和对照案例拒绝；同等表现优先选择纠正次数少和逻辑简单的方案。

候选搜索是对全部已打开development的回顾性搜索，不重新包装成前瞻验证。

## 3. 暴雨联合方案

选中方案：

```text
基础：heavy_rain_graphcast_scale_v2
纠正：同一案例—区域的24/48/72小时三个窗口
      均满足降水P95 / medium阈值 >= 0.25
      且至少1项水汽或动力条件支持
结果：基础low可在联合研究输出中纠正为medium
```

development结果：

| 指标 | 暴雨v2单独 | 联合方案 |
| --- | ---: | ---: |
| 事件目标窗 | 3/5 | 5/5 |
| 对照目标窗 | 4/4 | 4/4 |
| 事件案例检出 | 2/3 | 3/3 |
| 对照案例拒绝 | 2/2 | 2/2 |

两次正确纠正来自同一个事件案例，因此development满分不能解释为多事件泛化。

既有独立划分完整回放采用风险决策窗口口径：事件窗5/5、对照窗6/6，事件/对照案例—区域单位均为3/3。图谱触发0次，所以联合系统保持了暴雨v2原结果，但没有在独立划分中证明新的纠错增益。此前“6命中、12正确否定”是18个区域—lead的P95天气阈值口径，包含6个lead024非事件日；两组数字的评分单位不同，不能直接混用。

## 4. 高温联合方案

没有任何一组通过全部development门槛。按四项指标最弱项最大化选出的“最佳可用研究候选”为：

```text
基础：pooled_median_loco
纠正：订正温度距离高温阈值不超过1.0°C，且
      同一案例—区域三个lead都接近阈值，或区域最大值达到阈值
结果：候选日可由非高温纠正为高温
```

| 指标 | 基础方案 | 联合候选 |
| --- | ---: | ---: |
| 高温日召回 | 6/14 = 42.9% | 9/14 = 64.3% |
| 非高温日特异度 | 19/23 = 82.6% | 15/23 = 65.2% |
| 事件案例检出 | 4/9 = 44.4% | 6/9 = 66.7% |
| 对照案例拒绝 | 6/7 = 85.7% | 6/7 = 85.7% |

目标窗中的图谱升级有3次正确、4次错误，说明召回改善是以更多日级误报换来的。该候选没有通过特异度0.80和对照拒绝1.00门槛。

为避免只看一个排序结果，另保留两个明确运行点：

| 运行点 | 高温日召回 | 非高温日特异度 | 事件检出 | 对照拒绝 | 判断 |
| --- | ---: | ---: | ---: | ---: | --- |
| 平衡型（当前最佳可用） | 9/14 | 15/23 | 6/9 | 6/7 | 四项最弱值最高，但未过门槛 |
| 保守型 | 8/14 | 20/23 | 4/9 | 7/7 | 误报少，但漏报仍多 |
| 召回优先型 | 14/14 | 12/23 | 9/9 | 5/7 | 召回满分，但误报不可接受 |

三个运行点和全部2316组候选均写入机器可读CSV。不存在同时兼顾高召回和低误报的隐藏方案，因此没有用主观偏好把高温解锁。

既有高温独立划分包含一个事件、两个区域，共4个目标日：联合候选命中4/4、两个事件—区域单位均检出。但图谱触发0次，且独立划分没有任何高温对照，因此只能说明基础订正在该事件上召回良好，不能证明联合纠错能控制误报。

## 5. 最终运行口径

- 暴雨：联合方案可作为当前项目的整体研究输出；报告必须同时展示基础v2和图谱纠正。由于纠正增益只来自一个development事件且独立触发为0，不宣称生产验证完成。
- 高温：保存最佳联合研究候选和完整结果，但正式预警仍保持blocked。独立事件4/4不能覆盖development特异度失败和独立对照缺失。
- Forecast Agent不得读取本目录的观测评分文件，只能读取无真值预测锁。
- Verification在预测锁定后分别比较基础结果和联合最终结果。

## 6. 可复现证据

- 搜索配置：`configs/joint_pipeline_candidate_search_v2.yaml`；
- 联合图谱规则：`configs/joint_knowledge_correction_v3.yaml`；
- 运行策略：`configs/joint_operating_policy_v2.yaml`；
- 选择锁：`manifests/joint_pipeline_selection_lock_v2.json`；
- 全链回放：`manifests/joint_pipeline_full_chain_evaluation_v2.json`；
- 候选汇总和无真值预测锁：`handoff/model_selection/joint_v2/`；
- 开发集选择入口：`python -m saudi_warning.risk.select_joint_pipeline`；
- 独立划分回放入口：`python -m saudi_warning.risk.evaluate_joint_pipeline`。

一键复建开发搜索、独立回放和两份无真值报告：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/run_joint_pipeline_v2.ps1
```

报告使用`agent_joint_forecast_report_v4`，同时保留基础风险、图谱是否触发和联合最终风险。示例位于`handoff/reports/joint_pipeline_demo/`。它读取的预测锁不含`case_role`、同期观测、命中/漏报或灾害答案；高温报告会强制显示`research_only_blocked`。
