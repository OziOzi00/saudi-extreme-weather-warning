# 沙特 MAZU 极端天气预警项目：统一技术路线 v1

## 项目要解决什么

本项目构建面向沙特阿拉伯强降水与高温/热浪的可追溯预警原型：将气象预报转换为统一指标，依据可审查的风险规则生成区域风险结论，再用图谱组织证据和生成报告。

## 总体路线

```text
MAZU 2025 历史指标
  → 指标分布与候选阈值
  → 冻结风险规则 v1
  → 风险 JSON 生成方法

GraphCast 2020 历史预报
  → MAZU-like v1 指标（0.25 degree）
  → 已冻结的风险规则
  → 风险 JSON
  ├→ 无真值预测图谱 → 影子纠错 → Forecast Agent 可追溯预测报告
  └→ 预测输出锁定后 → IMERG/GHCN/灾害记录分层验证
                         → 评估图谱 → Verification 报告
```

MAZU 2025 用于开发、标定和内部一致性检查，不是未来预报模型。GraphCast 2020 用于规则冻结后的独立历史回放。Forecast Agent 不得读取2020同期或事后观测与灾害答案；预测输出锁定后，天气层验证和灾害影响层验证再分别进入 Verification 链。

## 当前实现状态

成员 A 已完成20个批准案例加1个demo的GraphCast读取、缓存、沙特区域处理、MAZU-like v1转换和24/48/72小时批处理：共63份NetCDF全部通过验收，并生成9009行ADM1摘要和交付溯源。A还协助完成MAZU 2025字段覆盖审计、13个ADM1区域注册和描述统计。

天气层已形成225/225条accepted development配对。暴雨v2已冻结并完成一次性独立评估；高温统一比较12组已开放development候选后仍无方案通过全部门槛，独立高温继续封存。综合暴雨评估图谱已在本地Neo4j Community 2026.06.0精确导入为87节点、152关系并通过固定查询；逐预测的`prediction_kg_bundle_v2`现已接入满足截止时间的WorldClim静态背景和v2影子纠错。影子纠错在development中补回1个漏报窗且未新增对照误报，但增益只来自1个事件案例，因此只能输出并列建议，不能替代或改写冻结风险结论。

## 三人边界

| 成员 | 负责 | 不负责 |
| --- | --- | --- |
| A | GraphCast → MAZU-like NetCDF、缓存、批处理 | 风险阈值与灾害结论 |
| B | MAZU 2025 统计、规则、风险 JSON、天气层评估 | 重算 A 的气象指标 |
| C | 区域与灾害真值、图谱、证据、报告 | 重算指标或风险分数 |
