# 数据契约 v1

本契约规定 A、B、C 的稳定交接格式。任何不兼容修改必须升级版本、提供迁移说明，并同步更新示例和测试。

职责分配不由本契约重复定义，详见[三人分工与协作流程](团队协作流程.md)。A 生产 NetCDF，B 生产 Risk JSON，C 消费风险结果并补充灾害影响事实；三方共同维护接口兼容性。

## A → B：MAZU-like NetCDF（已实现）

- 命名：`mazu_like_{YYYYMMDD}_{HH}_lead{LLL}.nc`，如 `mazu_like_20200820_00_lead024.nc`。
- 坐标：`latitude`、`longitude`；GraphCast 原生 `0.25 degree` 网格。
- lead 语义：lead024 = +6 至 +24 h；lead048 = +30 至 +48 h；lead072 = +54 至 +72 h。每个文件均为不重叠的 24 小时窗口。
- 必需变量：`daily_precip_total`、`t2m_c`、`tmax_c`、`tmin_c`、`wind10_speed`、`pwat`、`ivt`、`wind850_speed`、`wind_shear_850_200`、`omega500`、`geopotential_height500`；每个变量均有 `units`。
- 必需全局属性：`forecast_model`、`initial_time`、`lead_time_hours`、`valid_start_time`、`valid_end_time`、`source_resolution`、`indicator_version`、`window_steps`。

属性值中 `initial_time`、`valid_start_time`、`valid_end_time` 为 UTC ISO-8601；`lead_time_hours` 仅为 24、48 或 72；`forecast_model=GraphCast`、`source_resolution=0.25 degree`、`indicator_version=mazu_like_v1`。公式和单位见 [`../configs/indicator_mapping.yaml`](../configs/indicator_mapping.yaml)。

`handoff/region_summaries/` 是按统一 ADM1 边界生成的便利摘要，可供 B 开发 `indicator_summary`；它不替代本节的正式 NetCDF，出现差异时以 NetCDF 重新计算为准。

A 的文件只有通过 `python -m saudi_warning.forecasting.validate_mazu_like` 后才视为可交接。`manifests/delivery_manifest.csv` 保存逐文件 SHA-256、指标/实现版本指纹和验收状态；B 应在处理前复核 `validation_status=passed` 且当前文件 SHA-256 未变化。

## B → C：Risk JSON（暴雨研究回放已正式交付）

一个 JSON 对应一个 `case_id + region_id + hazard + lead`。文件命名建议为 `risk_result_{case_id}_{region_id}_{hazard}_lead{LLL}.json`。必须符合 [`../schemas/risk_result.schema.json`](../schemas/risk_result.schema.json)，可参考 [`../handoff/risk_results/example_risk_result.json`](../handoff/risk_results/example_risk_result.json)。

关键规则：

- 字段名使用稳定英文；可增加中文说明字段，但不能替换必填字段。
- 时间一律 UTC ISO-8601；数值单位要写入字段名（例如 `_mm`）或显式 `unit`。
- `region_id` 必须使用 C 发布的统一区域标识，不能仅依赖自由文本地名。
- `hazard` 仅为 `heavy_rain` 或 `heatwave`，`risk_level` 仅为 `low`、`medium`、`high`。
- `rule_status` 用于区分 `draft`、`frozen` 和接口 `example`；C 的正式链路只能消费显式标记为 `frozen` 的结果，字段缺失也不得视为已冻结。
- `verification` 在事前必须被 Forecast Agent 剥离；事后补充时，灾害影响状态只能为 `yes`、`no`、`unknown`，其中 `unknown` 不等于未发生灾害。
- Agent 不得改变 JSON 中的阈值、分数、证据或结论。

`handoff/risk_dry_runs/` 下的 JSON 只用于开发审计，不属于 B→C 正式交付。正式暴雨研究回放位于 `handoff/risk_results/development_heavy_rain/` 和 `handoff/risk_results/independent_heavy_rain/`，分别含 15 份与 18 份冻结结果；草案引擎仍拒绝把未冻结规则写入正式目录。高温尚无冻结正式结果。

## C：案例、影响真值、图谱与报告（开发接口已实现）

- 候选案例字段见 `schemas/candidate_case.schema.json`，版本化清单位于 `configs/case_catalog_candidates.csv`。只有 `selection_status=approved` 且经 B 完成天气筛选的案例才能进入正式回放。
- 灾害影响字段见 `schemas/disaster_impact_record.schema.json`；一行对应一个事件、区域、影响类别和来源。`unknown` 表示资料不足，不能自动转换成 `no`。
- 来源必须先登记在 `handoff/disaster_truth/source_catalog.csv`，真值记录通过 `source_id` 引用；仓库不复制网页全文。
- `prediction_kg_bundle_v2` 是预测态唯一允许输入的图谱快照，只能包含 `ForecastCase`、`ForecastWindow`、`Region`、`RiskAssessment`、`Rule` 和 `ConsistencyRule`；必须声明 `truth_access=forbidden`、`truth_accessed=false`。它不得包含观测、同期/事后灾害、影响、新闻或验证结论。
- 预测快照可额外包含`StaticPriorProfile`和`PriorSource`，前提是来源事实满足`available_at <= initial_time`。当前WorldClim画像必须保持`context_only`和`knowledge_prior_risk=null`，不能转成事件日风险。
- `kg_bundle_v1` 是结果锁定后的评估图谱，可保存观测、影响、验证及来源摘要；它不得输入 Forecast Agent，也不得把 2020 真值当作预测时可用知识。
- 默认 `scripts/run_agent_report.ps1` 生成 `agent_forecast_report_v3` 无真值预测报告；v3把基础风险与未激活影子建议分字段保存。只有显式运行 `scripts/run_agent_verification_report.ps1` 才生成 `agent_report_v1` 事后验证报告。
- 两类报告均不得改变冻结 Risk JSON。预测报告只能提示内部一致性冲突或合法的截止时点前知识先验；验证报告才可陈述命中、漏报、空报及灾害影响。
