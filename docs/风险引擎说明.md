# 风险引擎接口与边界

风险引擎由成员 B 主责。成员 A 已协助实现候选规则和可运行的草案引擎；`configs/heavy_rain_rules_v1.yaml` 与 `configs/heatwave_rules_v1.yaml` 仍为 `draft`，尚无经过团队评审和独立观测验证的冻结规则。时间口径见[指标时间语义与聚合口径](指标时间语义与聚合口径.md)，统计解释见[候选规则统计解释](候选规则统计解释.md)。

草案运行命令：

```powershell
$env:PYTHONPATH = "$PWD\src"
python -m saudi_warning.risk.run_draft
```

输出位于 `handoff/risk_dry_runs/`。引擎会拒绝让 draft 规则写入正式 `handoff/risk_results/`；当前正式目录仍只有 Schema 联调示例。

Risk JSON 可使用不依赖额外 Schema 库的验收命令检查必填字段、枚举、UTC 时间、24 小时窗口、lead/source 一致性、区域 ID、有限数值和重复结果：

```powershell
python -m saudi_warning.risk.validate_results handoff/risk_dry_runs/results
```

正式交付时增加 `--require-frozen`；缺少显式 `rule_status: frozen` 会被拒绝。

## B 的输入、处理与输出

1. 读取 A 的 `handoff/mazu_like/mazu_like_*.nc` 并校验 [数据交接契约](数据交接契约.md)。
   开发阶段可以用 `handoff/region_summaries/` 核对区域聚合，但正式风险结果必须能追溯回原 NetCDF。
2. 按 C 提供的统一 `region_id` 和边界进行区域聚合。
3. 使用 MAZU 2025 标定并冻结规则；记录 `rule_id`、版本、条件、权重和缺测策略。
4. 为每个区域、灾种、lead 写一个符合 Schema 的 Risk JSON。当前已完成 78 份草案试跑，正式 Risk JSON 必须等待规则冻结。

JSON 中必须给出区域级 `indicator_summary`、`supporting_evidence`、`contradicting_evidence`、`missing_evidence`。证据缺失不能伪装为支持或反对证据；没有观测/灾情资料时 `verification` 保持 `null` 或事后标为 `unknown`。

## 禁止事项

- 不得让 Agent 自行推导阈值或覆盖规则输出。
- 不得把 `draft` YAML 当作已验证规则。
- 不得以 2020 回放表现修改已冻结的规则后仍称其为独立测试。
