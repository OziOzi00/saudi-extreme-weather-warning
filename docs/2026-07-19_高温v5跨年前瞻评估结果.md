# 高温 v5 跨年前瞻 development 评估结果

## 结论

2018 年跨年前瞻批次已经按预注册候选完整执行。固定的 `lead_specific_median` 方法检出了 6 个观测高温日中的 5 个，召回率为 0.8333；但 12 个观测非高温日只正确否定 8 个，特异度为 0.6667。3 个事件案例检出 2 个，3 个对照案例只正确拒绝 2 个。

候选因此没有同时达到非高温日特异度不低于 0.80、对照案例拒绝率等于 1.0 的预注册门槛。结论为：**高温规则继续保持 `draft/blocked`，本轮候选不得冻结，独立高温案例继续封存。**

## 时序与数据边界

本轮遵守了“先锁、后看预测”的时序：

1. 仅使用 2018 NOAA SSODv2 观测选择 3 个事件和 3 个同区域对照；
2. 固定 24/48/72 小时订正值、阈值、持续日规则和成功门槛；
3. 将预注册锁提交并推送至主线；
4. 此后才读取 WeatherBench2 GraphCast 2018 数组并生成 18 份 MAZU-like NetCDF；
5. 评估只使用修正后的区域空间 P95，没有混合区域最大值，也没有在看到结果后搜索阈值。

一次网络超时只影响 `20180709_00` 的 step018 下载。断点续传后 72/72 个缓存时次和 18/18 份 NetCDF 均完成，未发现损坏的临时文件。

## 预注册门槛结果

| 指标 | 结果 | 门槛 | 是否通过 |
| --- | ---: | ---: | --- |
| 观测高温日召回率 | 5/6 = 0.8333 | ≥ 0.60 | 是 |
| 观测非高温日特异度 | 8/12 = 0.6667 | ≥ 0.80 | 否 |
| 事件案例检出率 | 2/3 = 0.6667 | ≥ 0.666667 | 是 |
| 对照案例拒绝率 | 2/3 = 0.6667 | = 1.00 | 否 |
| 事件/对照样本数 | 3/3 | 至少 3/2 | 是 |

天气日指标使用 `candidate_hot_day`；事件和对照的案例级风险指标使用“两日连续高温或单日严重高温”形成的 `candidate_positive`。两类指标没有混用。

## 案例级诊断

- `20180601_00 / SA-04`：事件检出。+48h 和 +72h 为连续候选高温日，+72h 同时达到严重高温阈值。
- `20180619_00 / SA-03`：事件未形成风险阳性。观测 +48h、+72h 均达到 47°C，但候选 +48h 只有 46.574°C，导致 +72h 的连续计数仍为 1。
- `20180709_00 / SA-04`：事件检出。三个候选日均跨过高温阈值，其中后两日与观测高温一致；+24h 是一个逐日误报。
- `20180614_00 / SA-04`：案例级正确拒绝，但 +48h 候选为 48.055°C、观测只有 43.0°C，出现一个孤立逐日误报。
- `20180623_00 / SA-03`：三个预报日均保持阈下，正确拒绝。
- `20180719_00 / SA-04`：案例级误报。+48h、+72h 候选分别为 48.249°C、48.591°C，观测分别为 45.0°C、44.0°C，连续两日越阈触发风险阳性。

4 个非高温日误报集中在 SA-04，说明从 2020 回顾性样本得到的统一正订正在 2018 的部分暖偏场景中发生了过订正。与此同时，SA-03 的事件 +48h 仍然偏冷。当前证据不支持用一个只依赖 lead 的固定正订正在不同区域、年份和天气过程间稳定泛化。

## 允许与禁止的后续工作

允许将本轮六个案例作为已经看过结果的 development 诊断样本，研究区域、季节、预报状态或起报前持续状态对误差的影响。如果设计 v6，必须先固定方法，再找新的未读取预测样本做前瞻验证。

当前禁止：

- 在这六个案例上搜索一个恰好通过门槛的新修正值或阈值，并把同一批结果称为前瞻验证；
- 因为高温日召回较高而忽略对照误报；
- 打开封存的独立高温案例用于选方法；
- 生成带有“已冻结、已独立验证”含义的正式高温 Risk JSON。
