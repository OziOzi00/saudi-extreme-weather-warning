# 知识图谱设计

## 定位

项目保留两类严格隔离的图谱：

1. **预测图谱**：只组织起报时允许使用的预测事实、静态区域资料、方法参考和历史先验；
2. **评估图谱**：保存2020真实观测、灾害影响、来源证据及命中/漏报/误报结果。

完整NetCDF栅格继续留在文件系统。Neo4j保存宏观实体、时间、来源、规则与推理关系，不替代气象数组存储。

## v1评估图谱：保留但不得作为预测输入

已有节点：`ForecastCase`、`Region`、`HistoricalEvent`、`Evidence`、`RiskAssessment`、`Rule`。

已有关系：`VALID_FOR`、`CONCERNS`、`HAS_EVIDENCE`、`EVALUATED_BY`、`BASED_ON`。

`heavy_rain_evaluation_bundle.json`包含2020真实事件、影响记录和来源，已通过本地Neo4j精确导入。它的用途是事后评估与审计。旧Agent沿`ForecastCase → HistoricalEvent → Evidence`读取同案例真值，因此旧报告只能叫验证报告，不能叫预测报告。

## v2无真值预测快照

`src/saudi_warning/knowledge_graph/prediction_bundle.py`为每个Risk JSON建立独立的`prediction_kg_bundle_v2`快照。

当前节点：

- `ForecastCase`：起报及知识截止时间；
- `ForecastWindow`：24/48/72小时有效窗口；
- `Region`：静态ADM1资料和边界代表年份；
- `RiskAssessment`：剔除事后verification的预测视图；
- `Rule`：冻结气象规则及其方法参考角色；
- `ConsistencyRule`：未验证的内部气象一致性检查规则。
- `StaticPriorProfile`：按ADM1与月份组织的WorldClim地形和长期降水背景，状态固定为context_only；
- `PriorSource`：来源URL、SHA、参考期、available_at和引用信息。

当前关系：

- `HAS_WINDOW`；
- `ASSESSED_AS`；
- `CONCERNS`；
- `USES_RULE`；
- `CHECKED_BY`。
- `CONTEXTUALIZED_BY`；
- `DERIVED_FROM`。

预测快照禁止出现HistoricalEvent、Evidence、Impact、ObservationTruth、VerificationResult及其敏感属性。自动验收同时检查`truth_access=forbidden`和`truth_accessed=false`。

## 时间与研究语义

未来正式先验事实必须同时记录：

- `valid_from/valid_to`：事实适用的时间；
- `available_at`：系统最早可以知道该事实的时间；
- `recorded_at`：本项目实际录入时间；
- `knowledge_role`：static_prior、historical_prior、forecast、observation_truth、impact_truth或verification_result；
- `sealed/sealed_until`：评估真值封印状态。

Forecast查询必须满足`available_at <= initial_time`。当前使用MAZU 2025方法参考回放2020案例，因此明确标记为`retrospective_transfer_replay`，不能包装成站在2020当时完成的实时业务预报。

## 语义标准复用

图谱v2采用“选择性对齐而非全量导入”：

- SOSA/SSN：观测、被观测属性、结果和过程；
- QUDT：物理量、量纲与单位；
- OWL-Time：时刻、区间与有效时间；
- PROV-O：生成、使用、派生和责任；
- GeoSPARQL：空间实体、几何及空间关系；
- SWEET：降水、气温、水汽、洪水和热浪等地球科学概念；
- UNDRR：Hazard、Exposure、Vulnerability、Capacity、Impact和Disaster Risk；
- SHACL：图谱结构和跨字段约束参考。

项目继续使用Neo4j属性图，不部署庞大的外部本体，也不声称执行完整OWL或GeoSPARQL推理。外部URI只用于概念对齐和数据互操作。

## 目标v2模块

后续按真实数据逐步增加，不预造空节点：

1. 空间时间：`GeometryVersion`、`TerrainFeature`、`TimeWindow`；
2. 气象语义：`IndicatorDefinition`、`ClimatologyProfile`、`ForecastValue`、`ObservationValue`；
3. 灾害机理：`HazardMechanism`、`TriggerCondition`、`InferenceRule`；
4. 风险语义：`KnowledgePriorAssessment`、`ExposureProfile`、`VulnerabilityProfile`、`ImpactRiskAssessment`、`IntegratedRiskAssessment`；
5. 来源断言：`Assertion`连接Source、事实、支持/反驳、审核状态与可用时间；
6. 验证语义：`TruthRecord`、`VerificationRun`、`VerificationResult`、`DatasetSplit`。

## 推理边界

图谱不能修改GraphCast数值或Risk JSON。目标输出分成：

```text
meteorological_risk   原气象规则结果
knowledge_prior_risk 预测前地形/历史/暴露先验
impact_risk          危险性×暴露度×脆弱性
conflict_flag        模型与先验或内部证据冲突
attention_level      不改变气象风险的人工关注等级
```

当前已实现合法截止时间前的WorldClim静态背景，`knowledge_prior_status=context_only`且风险为空；它只解释区域地形和月气候，不能识别事件日。旧内部冲突接口在development中补回2个漏报但产生3个误关注，已降级为失败诊断：保留`conflict_flag`供审计，但不得把低风险`attention_level`从`routine`升为`watch`。在补齐动态/更细空间信息并通过新development评估前，不得声称知识图谱已经能够纠正预测。

已预注册并复验的预测网格P99/最大值局地热点候选在15份development结果中触发0次，未减少漏报，已淘汰且未写入Forecast Agent关注逻辑。该失败结果保留在`development_spatial_diagnostics_v1.json`，用于证明“现有预测网格本身没有隐藏强降水热点”，不能继续把图谱描述成可凭聚合修正天气模型。
