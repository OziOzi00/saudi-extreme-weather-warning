# 知识图谱设计

## 定位

图谱组织“哪次预报、哪个区域、何种风险、基于何规则和证据、事后验证如何、数据来自哪里”。完整栅格和逐小时气象数据保留在 NetCDF，不进入 Neo4j。

## 当前已实现的开发子集

节点：`ForecastCase`、`Region`、`HistoricalEvent`、`Evidence`、`RiskAssessment`、`Rule`。

关系：`VALID_FOR`、`CONCERNS`、`HAS_EVIDENCE`、`EVALUATED_BY`、`BASED_ON`。

这一子集已经在 `src/saudi_warning/knowledge_graph/` 实现为可验证的开发 bundle。`neo4j/schema.cypher` 提供 Neo4j 5.x 唯一约束，`neo4j/queries/` 提供按 case、risk 和 region 查询的固定 Cypher。后续只有出现真实需求和明确数据来源时才扩展 `Model`、`TimeWindow`、`IndicatorSummary`、`VerificationResult` 等节点，避免先造空模型。

## 导入流程

```text
区域注册表 + 候选 case + 灾害影响真值 + Risk JSON
  → 跨文件 ID/状态校验
  → handoff/knowledge_graph/import_bundle.json
  → 本地 Neo4j 5.x（可选）
  → 固定查询
  → 受控 Markdown 报告
```

`import_bundle.json`仍是接口示例。`formal_development_bundle.json`接入15份冻结暴雨development Risk JSON，共69个节点、98条关系，并继续标记为`development_bundle`。综合development与独立暴雨结果的`heavy_rain_evaluation_bundle.json`已在本地Neo4j Community 2026.06.0精确导入为87个节点、152条关系，6个约束和三组固定查询均通过。该结果证明本地development实机兼容性，不代表生产部署或最终预警效果成立。

实机导入器使用参数化`UNWIND`。带`record_id`的影响证据关系以该字段作为稳定关系身份，以保留同一事件—来源之间的多条影响记录；其余关系按类型和端点幂等合并。自动验收会逐项比较节点ID和关系身份，而不只比较总数。

一键开发复验：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/run_c_development.ps1
```

本地Neo4j已启动且存在Git忽略的凭据文件时，可执行Schema、两次幂等导入和精确验收：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/run_neo4j_live_integration.ps1 `
  -Neo4jHome "D:\Soft\Neo4j\neo4j-community-2026.06.0"
```

实机证据和边界见[2026-07-17 Neo4j实机联调结果](2026-07-17_Neo4j实机联调结果.md)。

## 语义复用与实现边界

可将 SOSA/SSN（观测/预报）、QUDT（数值和单位）、OWL-Time（时间）、PROV-O（来源）和 DMDO（灾害/影响）作为参考映射。WeKG-MF、LinkClimate、DisasterLex 可作为结构或方法参考；XtremeKG、ST-FKG 仅是未来可能扩展。当前仓库未部署这些外部图谱，也不声称执行完整 OWL 或 GeoSPARQL 推理。

成员 C 使用 Neo4j Community 保存宏观关系和证据，并通过固定 Cypher/受控工具向报告模板提供查询结果。当前“Agent”是确定性模板，不调用大模型；这样可以验证证据边界并防止生成内容改写 B 的分数。未来如接入大模型，也只能消费同一受控查询结果。

`Region.region_id` 统一采用 `configs/region_registry.csv` 中的 `SA-xx` 标识。阿拉伯语区域名来源于沙特国家档案与记录中心行政区编码页面，总部对应关系参考沙特内政部；链接保存在注册表和来源目录。当前几何边界仍来自 `data/reference/saudi_adm1_geoboundaries_2017.geojson`，必须记录其 2017 代表年份和 ODbL 许可，不得声称为最新官方法定边界。
